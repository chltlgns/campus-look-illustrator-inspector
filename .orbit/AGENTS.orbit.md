# ORBIT Strict project contract

When `.orbit/state.json` exists, use the `orbit-strict` skill for project lifecycle work.
Read `.orbit/state.json` and `docs/orbit` before changing implementation. Do not enter
implementation until a digest-bound Gate request for the concrete scope/base is explicitly approved.
Create an isolated change worktree, run the committed quality profile, require a different verifier's
clean Trust receipt, and use ff-only integration. Preserve dirty/advanced targets and failed candidates.
Never treat credentials or a generic “proceed” as approval for a paid API call.
